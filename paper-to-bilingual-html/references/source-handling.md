# Source Handling

## Source Priority

1. 优先使用用户直接提供的原文件或正文文本。
2. 同时有 PDF 与可复制文本(如 arXiv HTML)时,优先以版面更可信、内容更完整的版本为准。
3. 如果 PDF 是双栏、扫描件或截图导出件,先确认阅读顺序,再开始翻译。

## PDF and OCR Workflow

1. 先识别标题区、作者区、摘要区、正文区、图表区、脚注区、参考文献区、附录区。
2. 双栏论文要警惕跨栏串读;用 `pdftotext -layout` 或 PyMuPDF 抽取后,按栏校对段落顺序。
3. 处理换行断词时,只有在原词边界明确时才恢复;不明确时保留原样并标注疑点。
4. 对页眉、页脚、页码、版权声明和会议信息:
   - 如果属于论文可读内容的一部分(如会议名称、DOI),保留一次即可。
   - 如果明显只是重复性版心噪声(每页重复的页眉页码),不纳入逐段主体,但不要误删真正的脚注或出版信息。
5. 图表中的可读文字、坐标轴标签、图例、表头、单元格文字应尽量提取;提取不全时以截图为准,文字作为补充。

## Segmentation Rules

1. 以原文可辨认的段落为最小对照单位。
2. 不要为了中文表达合并相邻英文段落。
3. 不要把一个英文段落拆成多个独立译文段,除非原文本身就是列表或表格行。
4. 列表项、脚注、参考文献条目可按单项单条处理。
5. 作者信息、机构、通讯作者说明、致谢等前置或后置材料,也按其原始顺序单独处理。

## Continuation Rules

1. 长文输出时,优先在章节边界、子章节边界或完整段落后停下。
2. 下一次必须从准确中断处继续,不要回顾式总结。
3. 不要因为篇幅限制切换成"后文略"或"以下总结"的模式。

## Escalation

以下情况要先向用户简短说明限制,再继续最保守的处理方式:

1. 源文件无法读取。
2. 大段内容完全不可辨认。
3. 表格或图中文字存在大面积缺失。
4. 版面顺序无法可靠恢复。

说明限制时,聚焦事实,不要猜测缺失内容。
